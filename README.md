BGP（Border Gateway Protocol，边界网关协议）是互联网上各个自治系统之间交换路由信息的协议。一句话概括：它负责告诉全世界的路由器，“哪些IP段归我，想到我这里该怎么走”。而所谓BGP VPS，就是商家在你的VPS和它的边界路由器之间开一条真正的BGP会话，让你能把自己的IP段公告到全网，流量经由商家的上游链路落到你的服务器上。

## VPS BGP到底是什么

一句话回答：BGP是自治系统之间互相“报路”的协议，BGP VPS则是把“报路”的资格交到你的虚拟机手里。

展开说，互联网由无数自治系统（AS）组成——运营商、数据中心、大型内容网络各是一个AS，每个AS用ASN标识。商家想让全世界知道“这些IP段的流量发给我”，靠的就是BGP：边界路由器不断向邻居广播自己能到达哪些段、走哪条路径，全网路由器据此选路。你可以把它理解成一套持续更新的全球导航系统。

普通VPS和BGP VPS的分野在这里。标准VPS上，你拿到的是商家IP池里的一个地址，地址属于商家——你退订，地址留下；换商家，IP就得换。BGP VPS上，你用自己的ASN通过eBGP会话接入商家路由器，VPS上跑的路由守护进程（BIRD2、FRRouting、OpenBGPD都是常见选择）把你的前缀公告出去，商家再传播给它的上游和对等网络，几分钟内全球路由表就知道“这个段可以从这家到达”。你的VPS从被路由的对象，变成了自己报路的一员。

## 自带IP公告，实际能换来什么

核心收益就一条：IP跟着你走，而不是跟着商家走。落到具体场景，是四种。

信誉跟着地址走。邮件送达率、各种防火墙白名单、DNS信誉，这些记录都挂在IP上。用商家分配的IP，换一次商家信誉就清零重建；用自己的段，搬到哪里地址都不变。

多宿主容灾。同一个前缀从两个地点分别公告，一家故障，流量自动走另一路，用户端感知不到。主备路径可以用LOCAL_PREF、MED或AS-path prepend来调节，这套机制是BGP的原生功能，不需要额外的负载均衡设备。

Anycast。同一个段从多地公告，用户被自动引到最近的节点。公共DNS根服务器和CDN边缘节点用的就是这个模式。

合规留痕。部分受监管的场景要求提供IP归属证明，通过RIR持有的地址段有完整档案可查。

## 开BGP会话前要备齐的六样东西

六样：ASN、IP段、IRR route对象、RPKI ROA、路由守护进程、支持BGP会话的商家。缺一样，会话都开不起来。

ASN是你在BGP互联网上的身份，向所在区域的RIR申请——欧洲是RIPE NCC，北美是ARIN，亚太是APNIC，一般经一家sponsoring LIR代办，RIPE的处理周期2到5个工作日。IP段方面，IPv4至少/24，IPv6至少/48，更小的段会被大多数网络直接过滤、公告不出去；IPv4从RIR直接拿越来越难，不少人转向经纪商租用，IPv6的/48则容易得多。

剩下三样都是配套材料。IRR route对象是在RIR数据库里登记“哪个ASN有权公告这个段”，不少上游直接拿IRR数据生成过滤规则，没有匹配记录的公告可能被静默丢弃。RPKI ROA用密码学方式把前缀和你的ASN绑定，目前全网超过51%的IPv4路由和57%的IPv6路由带有有效ROA，做来源校验的网络会拒收校验不过的公告。路由守护进程是VPS上跑的BGP软件，BIRD2、FRR、OpenBGPD三选一即可。

把这些时间加总，你大概能明白这事急不来：

| 材料 | 办理渠道 | 大致耗时 |
| --- | --- | --- |
| ASN | RIR（经sponsoring LIR） | 2–5个工作日 |
| IPv4 /24及以上 | RIR分配或经纪商租用 | 几天到几周 |
| IPv6 /48及以上 | RIR | 1–2个工作日 |
| IRR route对象 | RIPE Database等 | ASN下来后几分钟 |
| RPKI ROA | RIR会员门户 | 几分钟 |

从零开始，快则一两周、慢则一个月，才轮到第一次BGP会话。材料备齐后还有个容易踩的坑：BGP会话走TCP 179端口，你自己的防火墙要对上游对端IP放行179；打算用BFD做秒级故障检测的话，UDP 3784和3785也要一起开。

## 哪些人真的需要BGP VPS，哪些人多花钱

判断标准很直接：你是否拥有或租用自己的IP段，并且有理由控制它的路由。有，才值得往下看；没有，普通VPS是更省钱的选择。

这些场景对得上号：

- 运营小型ASN的网络人：想要一个公告点，又不想为整个机柜托管付费
- 换过商家、被IP信誉重建折腾过的人：自有段公告之后，搬家不再清零

这些场景别多花钱：普通建站、跑应用、高可用靠DNS failover或负载均衡就能解决的，BGP属于纯粹的冗余成本。

## 挑BGP VPS商家时该核对什么

重点是下面这几项，每一项都直接影响你后续的使用体验：

- **会话开通速度**：有的商家NOC几小时配好，有的要在工单队列里排一周，着急上线的话下单前问清楚
- **max-prefix限制**：每条会话能承载的路由条数有上限，比如Catalyst Host单会话限100条IPv4、50条IPv6，超限会话会被重置，公告前先算好自己要发几条
- **IRR过滤**：正经商家都按IRR数据做过滤，问清它认哪些数据库
- **RPKI**：越来越多商家要求ROA，有的直接拒收没有ROA的前缀，材料提前备好
- **DDoS**：防护是标配还是加购、清洗量多大。BGP本身不防攻击，但配合有清洗设施的商家，可以把受攻击的段引向清洗中心再回注，减少被打断的时间
- **IPv6**：原生IPv6 transit理应免费提供，单独收费的商家要留个心眼
- **BGP community**：能否用community控制路由向特定上游的公告方式，精细调度离不开它

## 常见问题

**没有ASN能买BGP VPS吗？**

开不了会话。BGP会话两端各是一个ASN，没有公网ASN就没有对端身份，商家无法受理公告。先申请ASN，再考虑BGP VPS。

**自己公告的IP，全网多久生效？**

会话建立、商家把公告传播出去之后，通常几分钟内全球路由表就能学到你的前缀。之后如果发生故障切换，时间取决于配置：默认hold timer下180–240秒，开了BFD可以到亚秒级。

**用了BGP就不怕DDoS了？**

BGP只是路由协议，攻击该来还是来。它的价值在于配合商家的清洗设施：把受攻击的段引向清洗中心再回注，让防护跟着你的IP一起搬家。

**BGP VPS比普通VPS贵在哪？**
